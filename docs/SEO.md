## Validation

- `npm run test:seo`: metadata/schema functions, script escaping, sample exclusions, robot-rule precedence, sitemap errors/dates, llms response and decoded asset formats. Includes real React SSR with deterministic API fixtures for the 21 page scenarios above, using the shared site layout. This does not launch a browser or the Next HTTP server.
- `npm test`: existing backend/frontend regressions plus the SEO checks.
- `npm run build`: Next production compilation and TypeScript checks.
- `npm run test:e2e`: extended with real HTTP checks for H1 counts, alt attributes, JSON-LD, crawler files, vehicle schema and asset MIME types. Requires the isolated local MySQL QA environment.

Latest results: all **129 source checks** passed (65 backend and 64 frontend, including nine SEO checks), and the production build including TypeScript passed. The HTTP suite was attempted but blocked before startup by `EPERM` when binding QA port 3100. No browser/HTTP pass is claimed for this change.

## Sitemap automation and status-code audit — 25 October 2026

The owner asked that every newly uploaded car's URL be added to the sitemap automatically, and for a check of missing SEO properties.

**Automatic sitemap inclusion already existed and was verified.** `app/sitemap.ts` is `force-dynamic` and reads `GET /api/v1/seo/listings` on every request, so a vehicle appears once it is approved and `published`/`reserved`, and leaves when it becomes `draft`, `sold` or `archived`. Samples are excluded. `lastmod` is the row's `updated_at`; view counting deliberately preserves it.

| Area                           | Finding                                                                                                                                                                                                                                                                                    | Change                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Removed/sold listing URLs      | Returned **200** (soft 404) to Googlebot and browsers. The root `app/loading.tsx` starts streaming before the page calls `notFound()`, fixing the status at 200 (Next 16 streaming contract). Googlebot is not in Next's blocking-metadata bot list, so it received the streamed response. | `proxy.ts` checks `/vehicles/:id/:slug` and `/cars/:id` against the new view-free `GET /api/v1/seo/listings/:id` before rendering. Missing → real **404** with the site's not-found page.                                                                                                                                                       |
| Outdated slugs and `/cars/:id` | Returned 200 with a client-side `<meta refresh>` instead of an HTTP redirect, and the page-level fallback used a temporary 307.                                                                                                                                                            | Proxy returns **308** to the canonical slug, preserving query strings. Page fallbacks use `permanentRedirect`.                                                                                                                                                                                                                                  |
| API outage on a listing        | Page rendered "temporarily unavailable" with 200.                                                                                                                                                                                                                                          | Proxy returns **503** with `Retry-After`, so crawlers retry instead of dropping the URL.                                                                                                                                                                                                                                                        |
| Unknown policy slugs           | Returned 200 + noindex.                                                                                                                                                                                                                                                                    | `generateStaticParams` + `dynamicParams = false` → real 404.                                                                                                                                                                                                                                                                                    |
| Image sitemap                  | Listing photos were not in the sitemap.                                                                                                                                                                                                                                                    | Each listing entry includes its public photos as `<image:image>` entries (absolute `/api/v1/media/:id` URLs, display order).                                                                                                                                                                                                                    |
| Instant discovery              | Google retired sitemap pings in 2023 and limits its Indexing API to job/livestream pages, so Google discovers new cars by recrawling the sitemap.                                                                                                                                          | Optional IndexNow (Bing, Yandex, Naver, Seznam; Bing also feeds Copilot/ChatGPT search). After a staff publish, or a status change into/out of public visibility, the backend posts the canonical URL. Production-only, off unless `INDEXNOW_KEY` is set; failures are logged and never block the staff action. Key proof: `/indexnow-key.txt`. |
| Ownership verification         | No way to add Search Console/Bing verification without code edits.                                                                                                                                                                                                                         | `GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION` env values render the meta tags. Verified with a separate API (:5002) and Next dev server (:3002) against the local database using a Googlebot user agent: live listing 200; wrong slug and `/cars/8` 308 to the canonical URL (query preserved); unknown listing, `/cars/99999`, `/vehicles/0/x` and `/policies/nope` 404 with noindex; listing during API outage 503; sitemap image entries, manifest, key file, verification tags and `lang` rendered. Automated: 135 unit/regression checks (69 backend, 66 frontend), typecheck, Prettier and a production build pass. The integration test was extended for the feed's images and the lookup endpoint but was not run here; HTTP E2E/browser suites were not rerun.

**Open crawl risk (not changed):** all server-side reads from Next reach Express from `127.0.0.1`, so they share one 300-requests-per-minute bucket. A vehicle page uses about five API calls (proxy check, metadata, page, similar vehicles, settings), so a crawl burst plus visitors can hit 429s, which surface as 503s or error states. Before launch, exempt trusted loopback server reads from the global limiter or forward a verified client IP; see OPERATIONS.md on `TRUST_PROXY`.

## When the domain is deployed

1. Deploy with `NEXT_PUBLIC_SITE_URL=https://ncrwheelz.com`, a working `API_URL`, HTTPS, and a redirect from the noncanonical HTTP/www host to the chosen domain. Rebuild after changing the public-site environment value.
2. Check the live `/robots.txt`, `/sitemap.xml` and `/llms.txt` return successfully. Confirm the sitemap contains current real inventory, with no samples or private routes.
3. Verify ownership in Google Search Console, submit `https://ncrwheelz.com/sitemap.xml`, and inspect the homepage, category and real vehicle URLs. This requires the owner's domain/account access.
   Set `GOOGLE_SITE_VERIFICATION` (and `BING_SITE_VERIFICATION` for Bing Webmaster Tools) if using the meta-tag method. For IndexNow, generate a key (for example `node -e "console.log(require('node:crypto').randomUUID())"`), set it as `INDEXNOW_KEY` in both backend and frontend, set backend `SITE_URL`, then confirm `https://ncrwheelz.com/indexnow-key.txt` returns it before publishing a car.
4. Validate a live real listing using Google's Rich Results Test and the Schema Markup Validator. Eligibility warnings depend on the content available; do not invent missing business or product facts to remove warnings.
5. Measure mobile Core Web Vitals/PageSpeed on the actual hosting environment and representative listings. Network speed, server response times, caching and real inventory images affect these results.
6. Approve the legal documents and real business details before deciding whether to make policy pages indexable. Keep customer documents behind authentication.
