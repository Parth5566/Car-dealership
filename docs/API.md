# REST API reference

Base path: `/api/v1`. The frontend proxies that path to Express using the server-only `API_URL`. All bodies are JSON except multipart uploads. Write requests require `X-NCR-Request: 1`; unexpected browser `Origin` values are rejected. Browser authentication uses HttpOnly access/refresh cookies. Cookie-authenticated requests must remain same-origin, or use explicit credentials for a trusted configured origin.

When transactional emails are enabled, successful contact/vehicle enquiries, test-drive requests and seller submit-for-review actions persist their notifications in `nw_email_outbox` within the same business transaction. The API response confirms that the request was saved; it does not claim inbox delivery. Draft saves do not enqueue seller emails. See [EMAIL.md](EMAIL.md) for setup, worker retries and operator commands.

Errors have shape `{error:{code,message,request_id?}}`. Validation returns 422, unauthenticated access 401, permission/CSRF failures 403, unavailable records 404, invalid transitions/conflicts 409 and upload size failures 413. Unknown server failures return a safe 500 message. Rate limits return 429. Credentials/document contents are never included in error responses.

## Public

Blog endpoints: `GET /blog` accepts `q`, `category`, `page` and `limit` (up to 12), and returns summaries of articles whose publication time has arrived. `GET /blog/:slug` returns one publicly available article or 404. `GET /blog-media/:id` serves a WebP asset only while selected as a cover or referenced by the body of a publicly available article. Draft, archived, future-scheduled and unused media remain private. `GET /seo/blog` returns publicly available article slugs, effective update times and cover URLs for the sitemap.

Protected blog endpoints under `/admin/blog` require content/settings permission: `GET /` lists posts (including a `scheduled` status filter), `GET /:id` reads an editor version, `POST /` creates a draft or validated publication, `PUT /:id` saves `{...content,version}`, and `PATCH /:id/status` accepts `{status,version}` for draft/published/archived. Stale versions and duplicate addresses return 409. The existing `author_name` field is article-specific; optional `publish_at` is an ISO timestamp with an offset. Future publication remains private until due, and edits preserve an article's original live publication date. Responses calculate `reading_minutes` and `word_count` from actual content, with the configured `reading_wpm` returned to the editor.

Rich `body` content uses a validated Tiptap JSON document with supported nodes/marks; legacy block arrays remain readable. Arbitrary HTML, unsafe URLs and unreviewed image nodes are rejected. Each `blogImage` stores its own `mediaId`, `alt`, `decorative`, `reviewed`, caption, width and alignment. All image IDs must belong to that post. Saves update media references transactionally with the article/version. `POST /:id/media` accepts multipart `file` up to 8 MB; photos are staged and normalized to WebP. `GET /:id/media` lists that article's private media library, and `GET /:id/media/:imageId` is authenticated and scoped to the post. See [BLOG.md](BLOG.md) for fields, migration and workflow.

Car valuation uses `GET /valuation/options`, `GET /valuation/catalog`, `GET /valuation/variants` and `POST /valuation`, without an account. With Scrappa configured it returns a CarDekho comparable asking-price range; otherwise it explicitly uses eligible local stock. One usable similar listing is sufficient. One/two-listing or identical-price ranges use a labelled site-defined ±10% band; three or more differing prices use their observed range. Variant and owner count are preferences rather than hard filters. All four endpoints share a 30-request/minute limit; provider cache/budget controls are separate. See [VALUATION.md](VALUATION.md) and [SCRAPPA.md](SCRAPPA.md). No customer/inventory records are changed.

Category meaning: `passenger` is a personal car; `commercial` is a yellow-plate passenger cab. Both seller categories can use the car catalog and variants. `min_payload` remains a legacy API parameter but is not shown or forwarded by the website’s cab filters.

Inventory parameters: `type` (`passenger`/`commercial`), `q`, `make`, `fuel`, `transmission`, `location`, `body_type`, `min_price`, `max_price`, `min_year`, `max_mileage`, `min_payload`, `featured=true`, `page`, `limit` (1–24) and `sort` (`newest`, `price_asc`, `price_desc`, `year_desc`, `mileage_asc`). Unknown status/visibility parameters cannot bypass the public predicate. Sort/SQL identifiers are allowlisted and values are parameterised.

Enquiry body: `name`, `email`, `phone`, `message`, `consent:true`, `consent_version:"contact-2026-10-21"`, optional `vehicle_id`, optional `source`. Contact details are normalised/limited. Consent time/revision are recorded with the request. Requests are rate-limited. If access expires while a refresh cookie remains, the API returns SESSION_EXPIRED before inserting; refresh and retry to retain account ownership. A visitor without either cookie receives AUTH_REQUIRED on protected routes and should not attempt refresh.

## Discounts and offers

`GET /offers` returns `{items}` containing only currently active published offers, ordered by featured status, display order and newest start. Drafts, scheduled offers and expired offers are excluded by the API. Public items omit the internal status, version and update timestamp.

All `/admin/offers` routes require staff authentication and the `settings` permission:

| Method and path                  | Behaviour                                                                                                                                           |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /admin/offers`              | Paginated `{items,total,page,pages,stats}`; `q`, `status=all/draft/active/scheduled/expired`, `page`; 12 items per page. Stats count all campaigns. |
| `GET /admin/offers/:id`          | Saved content, status, version and update time; missing offers return 404.                                                                          |
| `POST /admin/offers`             | Create from offer content and optional `status` (Draft by default); returns the saved offer, 201.                                                   |
| `PUT /admin/offers/:id`          | Replace offer content/status; requires the current numeric `version`.                                                                               |
| `PATCH /admin/offers/:id/status` | `{status: "draft" or "published", version}`; publication validates saved content and dates.                                                         |
| `DELETE /admin/offers/:id`       | `{version}`; permanently remove the offer while retaining its audit events.                                                                         |

Content: `title`, `description`, `benefit`, `eligibility`, `terms`, `badge`, `theme` (`gold/midnight/emerald/rose`), `pattern` (`glow/rings/grid/plain`), `icon` (`gift/sparkles/badge/truck`), `cta_label`, `cta_href` (`/contact`, `/cars`, `/commercial`), `coupon_code` (optional alphanumeric/hyphen/underscore reference), `featured` (boolean), `sort_order` (integer 0–9999), nullable `starts_at` and `expires_at` (ISO timestamps with timezone). Fields have server-enforced size limits. Unknown fields are rejected.

Drafts allow incomplete content. Publication requires title, description, benefit, eligibility, terms and both dates, with expiry after start and in the future. A future start schedules an offer; no background publishing job is needed. Writes lock the row and check its version; a stale version returns `409 STALE_OFFER` before mutation. Successful responses follow commit. All mutations are audited. Apply migration 004 first. Offers do not change vehicle prices.

## Authentication

| Method and path              | Behaviour                                                                        |
| ---------------------------- | -------------------------------------------------------------------------------- |
| `POST /auth/register`        | `{name,email,phone,password,consent:true}`; customer role only.                  |
| `POST /auth/login`           | `{email,password,scope?}`; `scope=admin` requires a staff account.               |
| `POST /auth/refresh`         | Rotates the refresh cookie. Replay revokes the family.                           |
| `POST /auth/logout`          | Revokes the refresh family and clears cookies.                                   |
| `GET /auth/me`               | Returns own safe profile and role permissions.                                   |
| `PATCH /auth/profile`        | Updates own permitted `{name,phone}` fields.                                     |
| `POST /auth/forgot-password` | `{email}`; generic response, or uniform delivery-unavailable when disabled.      |
| `POST /auth/reset-password`  | `{token,password}`; hashed single-use token, 30-minute expiry, revokes sessions. |

Passwords: customers require 6+ characters; staff require 12+ at both creation and reset. All passwords have a 72 UTF-8 byte limit. Hashes, raw tokens and refresh-session records are not returned in JSON. Session cookies and successful creation responses are emitted only after the transaction commits.

Vehicle shape: `type`, `make`, `model`, `variant?`, `year`, positive `price`, nonnegative `mileage`, optional `fuel_economy`, supported `fuel`, `transmission`, `location`, `body_type`, `owners`, `description`, deprecated optional `payload_kg` (legacy compatibility; cab forms send null), optional `seats`, `features[]`, optional `seo_title`, optional `seo_description`, `featured?`. Public fields and private seller contact/documents are separate entities.

`mileage` is the retained legacy API/column name for total kilometres driven (the odometer reading). `fuel_economy` is a separate optional positive number up to 1000, stored in the vehicle/submission JSON data: km/l for Petrol, Diesel and Hybrid; km/kg for CNG; km/kWh for Electric. Omitted values remain unknown; null or blank input clears the optional value. Existing odometer values are never converted into fuel economy. The website labels these as Kilometres driven and Mileage, with units. Changing between fuel types with different units clears the fuel-economy form input to avoid reinterpreting the previous number. No SQL migration is required for this additional JSON property.

## Administration

Inventory detail updates may include the `expected_version` returned by the detail API; the website supplies it and stale saves return `409 STALE_VEHICLE`. Published/reserved vehicles must first be moved to Draft. Edits synchronize linked seller vehicle details, record old/new values in audit/history, and clear inventory approval. A passenger/commercial category change also returns the seller submission to Under review with approval cleared, so its updated document checklist must be reviewed before publication.

All routes below also require staff authentication and the corresponding permission. Collections use `q`, optional `status`, and `page`, returning `{items,total,page}` with 20 rows per page.

Lead statuses: New, Contacted, Test Drive, Negotiation, Sold, Lost. Test drives: Requested, Confirmed, Rescheduled, Completed, Cancelled with validated transitions. Seller statuses: Draft, Submitted, Under Review, Information Required, Approved, Published, Rejected, Sold, Archived. Inventory: Draft, Published, Reserved, Sold, Archived. Server-side transition maps are the enforcement source, independent of what the UI displays.

Inventory photo mutations require Draft and invalidate approval. Approval requires Draft plus at least one photo. Reserved inventory can move directly to Draft. Missing photo IDs return 404. Lead search accepts a numeric ID or `NCR-<id>` in addition to name search. Note-only appointment edits can omit or send null `confirmed_at` to retain the existing schedule; confirming/rescheduling to a different status or time requires a future time.

Settings additionally accept `phone_secondary`, `hours`, `maps_url`, and `map_embed`. Maps URLs must be HTTPS Google Maps URLs; the embed must use `/maps/embed`. An explicit settings save activates `contact_customized=true`, replacing owner-supplied frontend contact defaults. This uses the existing JSON settings row and requires no schema migration.

## Approval versions, downloads and migrations

Inventory detail and review queue items include `expected_version`, a content digest of the inspected specifications/photos. `POST /admin/vehicles/:id/approve` requires `{expected_version}`. Missing versions return 422; changed content returns 409 STALE_REVIEW. Reload and inspect again before approving. Content reads do not reveal private storage keys.

Document metadata now includes `mime`, nullable `uploaded_at` and `updated_at` in addition to `created_at`. Only `uploaded_at` denotes a known upload/replacement time; legacy null values are not backfilled with review times. Protected download clients must use the common session refresh flow, rather than navigate directly to an API URL after an idle period.

Apply migrations 002 and 003 before starting this API version against an existing database. No existing consent or document upload history is invented.
